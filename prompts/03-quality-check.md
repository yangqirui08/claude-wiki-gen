# Prompt 03: Quality Check（章节自查）

> 每写完一章,在保存前跑一遍这份 checklist。任何一条不过 → 改完再保存。
> 全部章节写完后,再跑一遍**整体一致性**检查。

---

## A. 单章自查(写完保存前)

### 形式
- [ ] 文件名 = slug + `.md`
- [ ] 顶部 `# <title>` 一致
- [ ] "本章目标" 3 条
- [ ] TL;DR 段存在且 ≤ 5 句
- [ ] 章节顺序: Overview → Architecture → Components → Data Flow → (Implementation) → (Configuration) → (Pitfalls) → References → Related Pages

### Mermaid
- [ ] 数量 3-5(scope_hint 简单的章 3 个,复杂的 5)
- [ ] 至少 2 种不同类型(不能全是 graph TD)
- [ ] sequenceDiagram 必带 `autonumber`
- [ ] 暗色配色(节点 `#2d333b` + stroke `#6d5dfc` + text `#e6edf3`)
- [ ] 每图后有 `<!-- Sources: ... -->` 注释
- [ ] 没用 `<br/>`(用 `<br>` 或换行)
- [ ] hex 色号都是 6 位(`#fff` → `#ffffff`)
- [ ] **语法自查**(你无法真渲染,只能查常见硬错):
  - 每个 ` ```mermaid ` 有配对的 ` ``` ` 收尾
  - 节点 ID 不含空格 / 中文(中文放方括号 label 里,如 `A[中文]`)
  - 节点 label 里的特殊字符(`(` `)` `:` `,`)用双引号包,如 `A["foo(bar)"]`
  - 箭头语法正确(`-->` `->>`,不是 `—>` 全角)
  - `subgraph` 有配对的 `end`
  - sequenceDiagram 的 participant 在用之前先声明

### 引用
- [ ] 至少 5 个不同源文件被引用
- [ ] 链接格式: `[path:line](REPO_URL/blob/BRANCH/path#Lline)`
- [ ] 完整 URL,不是相对路径
- [ ] 行号准确(去文件实测——你刚才 Read 了的应该记得行号)
- [ ] 表格里有代码组件 → 必有 "Source" 列

### 内容深度
- [ ] **Overview 讲了 WHY**(为什么这个组件存在/解决什么问题)
- [ ] 至少 1 处解释了**设计权衡 / 替代方案为什么没选**
- [ ] 至少 1 个关键算法 / 流程有详细解释
- [ ] 没有"应该 / 大概 / 可能 / 估计 / 一般来说"这类**未读代码的臆测词**

### 中文质量
- [ ] 自然中文不机翻
- [ ] 专有名词保留英文(middleware / sandbox / agent),解释用中文
- [ ] 长句子拆短(超过 30 字必拆)
- [ ] 没有"诸如…等等" "及其相关的" 等冗词
- [ ] 专有英文名词**首次出现**给中文解释,如 "middleware(中间件,请求链拦截器)"
- [ ] 不堆术语显专业 — 描述设计时给**具体场景**,不堆"模式 / 抽象 / 实例化"这类元词
  - 反例:"通过策略模式动态选择算法实现"(依赖 GoF 设计模式知识,没读过的人不懂)
  - 正例:"用户切风险偏好时,按 risk='steady' 字符串去 slope_map 里查对应阈值"(说清场景 + 数据 + 动作,不依赖外部术语)
- [ ] 读者画像明确 — 按章节 level (Beginner / Intermediate / Advanced) 定调,Beginner 章不直接用还没解释的 Advanced 概念

### Related Pages
- [ ] 2+ 链接到其他章节
- [ ] 链接是相对路径 `./X-other-slug.md`
- [ ] 注明关系(不只是列名字)

---

## B. 整体一致性检查(全部章节写完后)

### 章节互引
- [ ] 每章 Related Pages 列的相关章节,**反向也提到**了本章
- [ ] 没有孤岛章节(完全没被任何其他章引用)
- [ ] 引用的 slug 实际存在

### 概念一致
- [ ] 同一个术语在不同章节用同一个中文翻译
  - 例: 不能 A 章叫"中间件" B 章叫"middleware" C 章叫"拦截器"
- [ ] 同一个组件的描述跨章一致(不要 A 章说它管 X B 章说它管 Y)

### 覆盖度
- [ ] 顶层每个主要目录(backend/ frontend/ skills/ 等)至少有一章覆盖
- [ ] 配置项(env / yaml / json)有一章集中说明
- [ ] 部署(docker / CI / 生产)有一章
- [ ] 测试策略有一章(如果项目有 tests/)

### 拓扑顺序
- [ ] Beginner 章不依赖 Advanced 章的概念
- [ ] 同 section 内章节顺序合理(配置 → 使用 → 内部实现)

### wiki.json 一致
- [ ] 所有 pages[] 对应的 .md 文件都存在
- [ ] 所有 .md 文件都在 pages[] 里
- [ ] slug / file 字段对应正确

---

## C. 重写信号

任一出现 → 直接重写该章,不要修补:

1. **臆测词触发**:Grep 自己写的内容,出现 "应该" "大概" "可能" "估计" 这些词 → 该段必须重写,要么补真证据,要么删
2. **Mermaid 灌水**:某图只有 2-3 节点 → 改成 list 或表格
3. **引用为零**:某段 3 句话以上没有任何引用 → 加引用或删段落
4. **OOP 框架病**:大段在讲"什么是设计模式"而不是"这个项目怎么用了它"
5. **README 复刻**:大段内容跟项目 README 重叠 → 你没产出新价值

---

## D. 时间盒

- 单章自查: 1-2 分钟(机械 checklist)
- 全体一致性: 全部章写完后 10 分钟
- 重写: 触发任一信号约 15-20 分钟/章

如果**3 章以上**触发重写信号 → 停下来反思:是不是 methodology / prompts/02 有问题? 改 prompts 再继续,不要硬扛。
